`appointments.booked_via` now accepts `'mcp'`; 188 rows intact, no `mcp` rows
yet (booking has never successfully run). MCP booking is no longer blocked at
the database. What remains is deploying Leuk to the new Vercel account.

**PHI-shaped tables are duplicated into `leuk-public`.** The `liminal` copy
brought the whole schema, app tables included, so `appointments` (186),
`clients`, `notes`, `messages` and friends now exist in BOTH databases. The
copies are inert — the app writes to `DATABASE_URL_PHI` — but the point of the
two-database split is that PHI lives in exactly one place, and right now it
doesn't. Worth dropping those tables from `leuk-public` once the cutover has
settled. Beware when counting rows: the same table name in both databases
returns different numbers, which is easy to misread as new activity.

### THE ROSTER LESSON, and it generalises

`aws bedrock list-inference-profiles` is a **catalogue, not an entitlement**. It
reports Claude Opus 5, Sonnet 5, Fable 5, Opus 4.7/4.8 and all three GPT-5.6
variants as ACTIVE on this account; every one throws AccessDeniedException when
called. Three more list as active and throw ResourceNotFoundException
(`nova-premier`, `claude-3-haiku`, `claude-sonnet-4`) — **44b's roster ships two
of those.** Neither 44b's nor Leuk's hand-maintained list is authoritative.

Each of the 27 ids in `src/lib/models.ts` was verified by **actually invoking
it**. Re-run that probe before adding anything anywhere:

```sh
aws bedrock-runtime converse --region us-east-1 --model-id "$M" \
  --messages '[{"role":"user","content":[{"text":"hi"}]}]' \
  --inference-config '{"maxTokens":1}'
```
